1. Executive Summary & Core Requirements

Balaji Earthmovers Kodoli is a specialized ERP system designed for earthmoving machinery contracting (JCBs, Poclain excavators, Tractors, Tippers, Rollers). It manages the complete lifecycle of heavy machinery deployment: hourly & fixed-amount billing, fuel tracking, 250-hour routine maintenance triggers, driver salaries with advances, customer receivables with passbook history, income/expense ledgers, multi-language localization, and dual PIN security.

Core Invariants That Must Be Preserved:

  • Dual Pricing Model: Work orders support both Hourly Work (hours × rate) and Fixed Amount (lump sum contract).
  • Atomic Income Linkage: When creating a work order, any initial payment received must automatically be recorded as an Income record and credited toward customer billings.
  • Atomic Rollback on Deletion: Deleting a work order must reversibly deduct from customer total billed, customer total paid, vehicle worked hours, and soft-delete the linked initial payment.
  • Exact Net Earnings Formula: Net Earnings = Total Collected Income - Total Expenses. Total Work Billed is gross invoiced volume, not actual cash-in-hand.
  • 250-Hour Maintenance Engine: Machines flag a 250h SERVICE DUE! alert when (workedHours - lastServiceHours) ≥ 250.0. The Reset button must be positioned below the machine details.
  • Dual PIN Security: 4-digit App Unlock PIN (default 1234) with an animated green open-lock unlock transition, plus a 4-digit Admin PIN (default 2476) required for sensitive edits, deletions, and data wipes. PINs must never be revealed in UI hints.
  • WhatsApp-Style Compact Interface: Compact lists featuring left avatar/machine badges, bold titles with dates, subtle subtitle details, status pills on right, and tight padding with zero top dead space.
  • Passbook Ledgers: Both Drivers and Customers must have a dedicated timeline Passbook (debits vs credits, running balance, call button, and payment drawer).

3.2 Complete PostgreSQL / TypeORM Entity Definitions

1. Vehicle Entity (vehicles)

@Entity('vehicles')
export class Vehicle {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column({ length: 100 })
  vehicleName: string; // e.g. "JCB 3DX", "Dumper", "Other"

  @Column({ length: 50, unique: true })
  vehicleNumber: string; // e.g. "MH-09-AB-1234"

  @Column({ length: 100, default: '' })
  model: string;

  @Column('decimal', { precision: 10, scale: 2, default: 0.0 })
  workedHours: number;

  @Column('decimal', { precision: 12, scale: 2, default: 0.0 })
  fuelExpenseTotal: number;

  @Column('decimal', { precision: 10, scale: 2, default: 0.0 })
  lastServiceHours: number; // Checked against 250hr interval

  @Column({ nullable: true })
  currentDriverId: string;

  @ManyToOne(() => Driver, { nullable: true, onDelete: 'SET NULL' })
  @JoinColumn({ name: 'currentDriverId' })
  currentDriver: Driver;

  @CreateDateColumn()
  createdAt: Date;

  @UpdateDateColumn()
  updatedAt: Date;

  @DeleteDateColumn({ nullable: true })
  deletedAt: Date;
}

4. Work Entity (works)

@Entity('works')
export class Work {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column({ length: 150 })
  workName: string;

  @Column()
  vehicleId: string;

  @ManyToOne(() => Vehicle, { onDelete: 'RESTRICT' })
  @JoinColumn({ name: 'vehicleId' })
  vehicle: Vehicle;

  @Column()
  driverId: string;

  @ManyToOne(() => Driver, { onDelete: 'RESTRICT' })
  @JoinColumn({ name: 'driverId' })
  driver: Driver;

  @Column()
  customerId: string;

  @ManyToOne(() => Customer, { onDelete: 'RESTRICT' })
  @JoinColumn({ name: 'customerId' })
  customer: Customer;

  @Column('bigint')
  date: number; // Unix Epoch ms

  @Column('bigint')
  startTime: number;

  @Column('bigint')
  endTime: number;

  @Column('decimal', { precision: 8, scale: 2 })
  totalTimeHours: number;

  @Column('decimal', { precision: 10, scale: 2 })
  hourlyRate: number;

  @Column('decimal', { precision: 12, scale: 2 })
  totalWorkAmount: number;

  @Column({ length: 200, default: '' })
  location: string;

  @Column({ default: false })
  isFixedAmount: boolean;

  @DeleteDateColumn({ nullable: true })
  deletedAt: Date;
}

4. Mathematical Models & Business Logic Invariants

CRITICAL MATHEMATICAL INTEGRITY RULES
Failure to adhere to these transactional equations will result in ledger drift. All database state transitions must execute inside PostgreSQL transactions (queryRunner.startTransaction()).

4.1 Work Creation & Automatic Driver Assignment

  1. Vehicle & Driver Linkage: When a user selects a vehicle in the Work Entry Dialog, the frontend automatically looks up vehicle.currentDriverId and pre-selects that driver. The user can manually override the driver if desired.
  2. Pricing Option:
    • If isFixedAmount == false: totalWorkAmount = totalTimeHours * hourlyRate.
    • If isFixedAmount == true: totalWorkAmount = fixedAmount. The hourlyRate is set to fixedAmount / totalTimeHours (or 0.0 if hours is 0).
  3. Initial Payment Booking (Atomicity):

    If initialPaidAmount > 0 during Work creation:

    await queryRunner.manager.insert(Work, workEntity);

if (initialPaidAmount > 0) {
  const incomeEntity = new Income({
    workId: workEntity.id,
    customerId: workEntity.customerId,
    date: workEntity.date,
    totalWorkAmount: workEntity.totalWorkAmount,
    paidAmount: initialPaidAmount,
    pendingAmount: workEntity.totalWorkAmount - initialPaidAmount,
    paymentMode: dto.paymentMode,
    transactionReferenceId: dto.transactionRef || ''
  });
  await queryRunner.manager.insert(Income, incomeEntity);
}

// Update Customer aggregate balances
await queryRunner.manager.increment(Customer, { id: workEntity.customerId }, 'totalBilled', workEntity.totalWorkAmount);
await queryRunner.manager.increment(Customer, { id: workEntity.customerId }, 'totalPaid', initialPaidAmount);
await queryRunner.manager.update(Customer, { id: workEntity.customerId }, {
  pendingBalance: () => 'totalBilled - totalPaid'
});

// Update Vehicle hours
await queryRunner.manager.increment(Vehicle, { id: workEntity.vehicleId }, 'workedHours', workEntity.totalTimeHours);

4.2 Atomic Work Deletion & Reversion

When an administrator deletes a Work order (verified by 4-digit Admin PIN 2476): 

// 1. Fetch Work and any linked incomes
const work = await queryRunner.manager.findOne(Work, { where: { id: workId } });
const incomes = await queryRunner.manager.find(Income, { where: { workId, deletedAt: IsNull() } });
const totalIncomeForWork = incomes.reduce((sum, inc) => sum + Number(inc.paidAmount), 0);

// 2. Soft-delete Work and Incomes
await queryRunner.manager.softDelete(Work, workId);
if (incomes.length > 0) {
  await queryRunner.manager.softDelete(Income, { workId });
}

// 3. Roll back customer balances
await queryRunner.manager.decrement(Customer, { id: work.customerId }, 'totalBilled', work.totalWorkAmount);
await queryRunner.manager.decrement(Customer, { id: work.customerId }, 'totalPaid', totalIncomeForWork);
await queryRunner.manager.update(Customer, { id: work.customerId }, {
  pendingBalance: () => 'GREATEST(0, totalBilled - totalPaid)'
});

// 4. Roll back vehicle hours
await queryRunner.manager.decrement(Vehicle, { id: work.vehicleId }, 'workedHours', work.totalTimeHours);

4.4 250-Hour Routine Maintenance Trigger

  • Calculation: hoursSinceService = vehicle.workedHours - vehicle.lastServiceHours.
  • Threshold: If hoursSinceService ≥ 250.0, vehicle triggers isServiceDue = true.
  • UI Representation: Displays a red warning banner with machine name, current hours, and overdue hours.
  • Reset Button Rule: The "Reset 250h Service" button must be placed below the machine details. Resetting updates lastServiceHours = vehicle.workedHours.
